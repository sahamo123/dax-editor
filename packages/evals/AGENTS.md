# packages/evals

Measures how well a model edits video. Root rules in `/AGENTS.md` apply; read `docs/evals/README.md` first.

## Concepts

- **Task** (`tasks/*.json`): footage fixture + plain-language prompt + checks. Validated by `EvalTaskSchema`.
- **Check**: a pass/fail condition on the *finished timeline*, never on how the model got there.
- **Adapter** (`ModelAdapter`): one way of attempting tasks (a local model, a hosted API, the oracle).
- **Oracle**: a hand-written solver. Not a model. It proves the harness works and shows the best possible score. If the oracle fails a task, the task or checker is wrong.

## Adding things

- **A task:** add `tasks/<id>.json` (id is kebab-case and must match the oracle's `switch` if you want the oracle to solve it), run `pnpm eval --adapter oracle`.
- **A check type:** add a variant to `CheckSchema` in `src/task.ts` and handle it in `src/score.ts`. Keep checks outcome-based.
- **An adapter:** implement `ModelAdapter` in a new file, register it in `makeAdapter` in `src/cli.ts`, and record tokens and invalid tool calls honestly in `AgentResult`.

## Rules

- Fixtures are generated by FFmpeg (`src/fixtures.ts`), never committed.
- Evals never call the network by default. Adapters that need a model server must fail with a clear message if it is unreachable.
- Results are comparable only if tasks, fixtures and sampling settings are identical. Do not edit an existing task's checks to make a model pass; add a new task instead.
