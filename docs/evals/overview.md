# Evaluation harness overview

`packages/evals` answers one question repeatably: **given a request in plain language and some footage, can this model produce the right edit?**

## How it works

1. A **task** (`packages/evals/tasks/*.json`) names a synthetic **fixture** (footage generated by FFmpeg), a **prompt** (what the user would type) and **checks**.
2. The runner builds a project containing the fixture and gives a **model adapter** a `Session` to edit.
3. After the adapter finishes, the **checks** inspect the finished timeline (and, for silence, the rendered output). They never look at what the model said.
4. A **record** is written per run: pass/fail, failure reasons, turns, tool calls and how many were invalid, tokens, latency.
5. Records are summarized into a table: pass rate, median latency, mean turns, invalid tool-call rate, output tokens per second.

## Adapters

| Adapter | What it is | Status |
|---|---|---|
| `oracle` | A hand-written solver that knows each task. Not a model. It proves the harness and checks are correct and shows the best score possible. | Done, passes 3/3 |
| OpenAI-compatible | Any server that speaks the OpenAI chat-completions API with tool calling: Ollama, llama.cpp's `llama-server`, LM Studio, vLLM, hosted APIs. | Next |
| Anthropic | Claude models through the Anthropic API. | Later |

If the oracle ever fails a task, the task or the checker is wrong, not a model.

## Running

```sh
pnpm build
pnpm eval --adapter oracle                # prints PASS/FAIL per task and a summary table
pnpm eval --adapter oracle --out out.json # also writes the raw records
```

CI runs the oracle so a broken harness is caught immediately.

## Adding a task

1. Create `packages/evals/tasks/<kebab-case-id>.json`:
   - `fixture`: a name from `FIXTURE_NAMES` (add new footage in `src/fixtures.ts`),
   - `prompt`: what the user would say,
   - `checks`: outcome checks (`duration`, `clipCount`, `noSilenceLongerThan`; add more in `src/task.ts` and `src/score.ts`).
2. Teach the oracle the solution (`src/oracle.ts`) so the task is validated.
3. Run `pnpm eval --adapter oracle`.

Never loosen an existing task's checks to make a model pass. Add a new task instead, so scores stay comparable over time.

## Adding a model adapter

Implement `ModelAdapter` (`src/runner.ts`): given an `AgentContext`, edit `ctx.session` using whatever tool-calling loop you have, and return honest counts of turns, tool calls (and how many were invalid) and tokens. Register it in `makeAdapter` in `src/cli.ts`. Fail with a clear message if the model server is unreachable.

## What it deliberately does not do (yet)

- It does not judge taste (pacing, which animation looks nicer). That needs human rating, planned in the [model evaluation plan](/evals/model-evaluation-plan.md).
- It does not test vision (understanding frames). Text-only perception comes first.
- It does not yet include speech: transcripts will be supplied by fixtures so tasks do not depend on a speech model.
