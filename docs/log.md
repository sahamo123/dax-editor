# Project log

## 2026-10-19
* **Update**: A/V drift after cuts is fixed in the render and the model. Each source is converted to the project rate once before any trim (one `fps` pass, split per clip), and cut points are put on the project's frame grid in `timeline.ts` (plan cuts from `cuts.ts` go through the same path). Before the fix, 60 joins drifted by about 0.5 s (59.94 CFR source) and 1.6 s (VFR source) between the timeline and the picture or sound. After it, both ends are within 0.7 ms of the timeline, and picture and sound agree to 0.7 ms. Tests in `av-sync-render.test.ts` and `timeline-grid.test.ts`. Breath attenuation from the same research note is not built. See [A/V sync and breath recipes](research/av-sync-and-breath-recipes.md).

* **Creation**: Tauri 2 desktop shell (`apps/desktop/src-tauri`) that supervises the engine-server sidecar. Verified on Linux with Xvfb: the sidecar starts, its loopback API answers with the bearer token, and closing, SIGTERM or SIGKILL of the app leaves no server or child process. macOS and Windows installers, signing, notarisation, the updater and the release workflow have not been run. The packaging decision is [ADR 0010](/adr/0010-desktop-sidecar-packaging.md).

* **Creation**: effects layers in `@dax/core`, spec [effects layers](/specs/effects-layers.md). Zoom (`zoom.ts`: hard punch-in or slow push-in with easing and a focus point, rendered with `scale eval=frame` and `crop`), music and sound effects with automatic ducking (`audio-layer.ts`: `sidechaincompress` keyed by a levelled copy of the main audio so a quiet speaker ducks the music as deeply as a loud one, one `amix`, a limiter at about -1 dBFS), and image overlays (`image-overlays.ts`: PNG or JPG, five presets, the text animations). Ten new commands (`add_zoom`, `update_zoom`, `remove_zoom`, `add_audio`, `update_audio`, `remove_audio`, `set_ducking`, `add_image_overlay`, `update_image_overlay`, `remove_image_overlay`), 45 in all. Repeating an `add_*` command updates instead of duplicating. Music is anchored to the timeline and is not cut by ripple deletes; zooms, images and sound effects follow the footage. Tests render real video and measure it: box edges for zoom factor and anchor, band-limited RMS for duck depth and timing, peak level for clipping, colour and bounds for logos.
* **Update**: templates apply zoom, music and logo steps. A template file has a new `effects` list; the `music-bed`, `audio-ducking`, `zoom-keyframes` and `image-overlays` features left `ENGINE_FEATURES`, and two new ones name what is still missing (`focus-detection`, `graphic-cards`). 41 steps across the 34 templates moved from `deferred` to `effects`; the rest keep an accurate `requires`. `apply_template` takes `music` and `logo` (a path or an asset id); templates never ship music or logos.
* **Update**: `parseProbe` now reports PNG and JPEG files as `image` assets (they used to look like one-frame videos with a zero duration).
* **Creation**: `packages/bridges` (`@dax/bridges`), the CLI sign-in bridges. The Claude Code bridge spawns the user's own signed-in `claude` in print mode. It starts a loopback MCP endpoint on the engine's live `Session` with a per-run token, restricts the CLI to `mcp__dax__*` (all built-ins off, denial instead of prompts), maps the stream-json events to chat events, and cancels with SIGTERM then SIGKILL. Detection uses only the CLI's own `auth status`, and the environment is an allow-list, so API keys and OAuth tokens are never passed. Codex is detection only, and Gemini is deliberately not supported. `@dax/engine` `launch()` wires the bridges in by default and reports real `cli-*` statuses. See [CLI bridges](architecture/cli-bridges.md) and the [research](research/cli-subscription-bridges.md). Tests use a fake `claude` and a trimmed recording of a real run, with no network. Found while building: a recorded run whose environment had proxy variables but no `NO_PROXY` reported the loopback MCP server as failed. After the bridge began adding loopback to `NO_PROXY`, the same run connected. The cause is not confirmed, so the bridge always exempts loopback as a precaution. A pre-existing typecheck error in `packages/engine/src/runner.test.ts` (`new Session()` without a project) was left as it was.

* **Update**: reconciled the desktop UI with the real engine. The UI had been built against a hand-written mock and guessed several API shapes; `@dax/server` is the source of truth, so the shared shapes (local model status, job and chat replies, import result) now live in `@dax/protocol` as zod schemas and the UI uses them. Mismatches fixed: the local model API (one `POST` with an action and a `recommended` field in the UI, versus a flat status and one endpoint per action on the server), the export end-of-job announcement (the server replies when FFmpeg starts), partial import failures, `signedIn: false` claimed for CLIs the engine cannot drive, and a cached `GET /api/providers` behind the "Check again" button. Server additions: `POST /api/local-model/uninstall`, optional `label`/`description`/`supported` on the status. The Playwright mock is now the real server with injected fakes, and `e2e/real-engine.spec.ts` runs the app against the real `dax-engine` (import, manual edit, media over the token URL, settings and API key, chat through the real agent). See [product v1](/specs/product-v1.md). After the editor module merged, the media formats it had guessed (waveform array, filmstrip frame size) were replaced by the server's: `WaveformSchema`, the 96x54 filmstrip constants and `PresetInfo.style` are now in `@dax/protocol`, and the editor reads them.
* **Milestone**: `pnpm check` exits 0 across all packages. Tests pass: 365 core, 292 desktop, 157 agent, 116 server, 52 MCP, 25 CLI, 21 evals, 5 protocol, 3 engine and 14 script. The merged work is on branch `claude/exciting-lamport-1k91fh`. It is not yet on `main` and nothing has run on GitHub CI.
* **Creation**: `@dax/agent` (`packages/agent`): a provider-neutral tool loop that turns a chat message into edits by calling the command registry. It has OpenAI-compatible and Anthropic providers and reliability features for small models: JSON repair, and recovery of tool calls written as plain text. Eval adapters in `packages/evals` score any provider on the same loop the product uses, and report the tokens and invalid tool calls the backend actually returned.
* **Creation**: skills layer. 24 `SKILL.md` playbooks in `skills/`, plus a router skill. The loader and router are in `packages/core/src/skills.ts`. They pick the few skills that fit a request, within a character budget, so a small model is not flooded with context.
* **Creation**: templates. 34 style and industry recipes (16 styles, 18 industries) in `templates/`, a deterministic applier in `packages/core/src/templates.ts`, and the `list_templates` and `apply_template` commands. Templates are data only. An applied template is one history entry, so one undo reverses it.
* **Creation**: `@dax/server` (`packages/server`, bin `dax-server`): the local HTTP and WebSocket engine server, implementing `@dax/protocol` over the command registry. It serves media with HTTP Range support and checks the bearer token, Host and Origin on every request.
* **Creation**: `@dax/engine` (`packages/engine`, bin `dax-engine`): a launcher that starts the server with the agent, skills and provider registry wired in. It also takes an optional local model and speech-to-text. Transcriber hooks were added to the server and agent for when a speech engine lands.
* **Creation**: desktop app in `apps/desktop`. The app shell has chat, settings, history, a media bin and a client that reconnects. The editor module has a gapless two-video preview, a CSS overlay preview matched to the FFmpeg output, and a pointer-driven timeline with reorder, trim, split, fades, volume, overlay lanes, snapping and zoom. It also has drag-and-drop animation presets and an inspector. Root scripts now include `apps/*`. Playwright tests are in `apps/desktop/e2e`.

* **Creation**: `packages/mcp` (`@dax/mcp`, bin `dax-mcp`) and `packages/cli` (`@dax/cli`, bin `dax`). The MCP server generates one tool per core command from `commandTools()`, maps `readOnly`/`irreversible` to MCP annotations, adds a `preview_frame` image tool, project and history resources, export progress and cancellation, and runs over stdio or loopback Streamable HTTP with a bearer token and Host/Origin checks (built on `@modelcontextprotocol/server` 2.3.1, as the [MCP design research](/research/mcp-server-design.md) recommends). The CLI runs any command on a `.dax.json` project with `--json` output and exit codes, and starts the MCP or engine server. Both run the registry in-process, see [CLI and MCP server](/architecture/cli-and-mcp.md). Found while building: `save_checkpoint` changes only in-memory history, so both front doors call `session.save()` after editing commands; core cannot interrupt an FFmpeg render, so a cancelled MCP export finishes in the background and its file is deleted.

* **Creation**: command registry in `packages/core/src/commands.ts`. It has 33 commands and is the only way a project changes: the UI, built-in AI, MCP and CLI all call it. Each command has typed arguments, a description written for models, `readOnly` and `irreversible` flags, and JSON-schema tool specs. An end-to-end test showed `remove_silences` and `remove_fillers` were not idempotent. Fixed, with a regression test.
* **Creation**: text overlays (`overlays.ts`, `overlay-filters.ts`, `presets.ts`) for titles, lower-thirds, captions and callouts, with six animation presets rendered by FFmpeg `drawtext`. User text goes to files, so it cannot break or inject into the filter graph. Overlays follow ripple deletes. Every preset was rendered and checked frame by frame. Inter (OFL-1.1) is bundled.
* **Creation**: cut engine (`cuts.ts`). Speech detection is relative to each recording's noise floor, with hysteresis, so it works in noisy rooms where a fixed threshold misses pauses. Five presets (gentle, standard, tight, podcast, tutorial). Every decision has a kind, reason, confidence and status. False starts and repeated takes are proposals only. Commands: `plan_cuts`, `apply_cut_plan`, `smart_cut`. Research: [cut intelligence](/research/cut-intelligence.md).
* **Creation**: word-timed captions (`captions.ts`), computed from clip transcripts at render time so they follow every cut. Three looks (classic, bold-pop, minimal) burned in via ASS subtitles. Command `set_captions`. Captions need a transcript, and no speech engine exists yet.
* **Creation**: fit modes (contain, cover, blur) and output presets via `set_format`, including portrait 1080x1920 and square. Portrait and square default to blur. Clip fades, plus 8 ms audio fades at real cuts so joins do not click.
* **Creation**: session history is a tree (`session.ts`). States carry a source (manual, ai or template). You can jump to any state, save named checkpoints, and undo then edit keeps the old branch.
