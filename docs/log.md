# Project log

## 2026-10-18

* **Update**: reconciled the desktop UI with the real engine. The UI had been built against a hand-written mock and guessed several API shapes; `@dax/server` is the source of truth, so the shared shapes (local model status, job and chat replies, import result) now live in `@dax/protocol` as zod schemas and the UI uses them. Mismatches fixed: the local model API (one `POST` with an action and a `recommended` field in the UI, versus a flat status and one endpoint per action on the server), the export end-of-job announcement (the server replies when FFmpeg starts), partial import failures, `signedIn: false` claimed for CLIs the engine cannot drive, and a cached `GET /api/providers` behind the "Check again" button. Server additions: `POST /api/local-model/uninstall`, optional `label`/`description`/`supported` on the status. The Playwright mock is now the real server with injected fakes, and `e2e/real-engine.spec.ts` runs the app against the real `dax-engine` (import, manual edit, media over the token URL, settings and API key, chat through the real agent). See [product v1](/specs/product-v1.md).
* **Milestone**: `pnpm check` exits 0 with 124 core, 5 protocol, 6 evals and 14 script tests passing.
* **Decision**: autonomous open-source intake, [ADR 0009](/adr/0009-autonomous-open-source-intake.md). Scout agents may adopt qualifying open-source tools by pull request without human approval, within the intake policy's hard gates. The escalation list is absolute.
* **Creation**: command registry in `packages/core/src/commands.ts`. It has 33 commands and is the only way a project changes: the UI, built-in AI, MCP and CLI all call it. Each command has typed arguments, a description written for models, `readOnly` and `irreversible` flags, and JSON-schema tool specs. An end-to-end test showed `remove_silences` and `remove_fillers` were not idempotent. Fixed, with a regression test.
* **Creation**: text overlays (`overlays.ts`, `overlay-filters.ts`, `presets.ts`) for titles, lower-thirds, captions and callouts, with six animation presets rendered by FFmpeg `drawtext`. User text goes to files, so it cannot break or inject into the filter graph. Overlays follow ripple deletes. Every preset was rendered and checked frame by frame. Inter (OFL-1.1) is bundled.
* **Creation**: cut engine (`cuts.ts`). Speech detection is relative to each recording's noise floor, with hysteresis, so it works in noisy rooms where a fixed threshold misses pauses. Five presets (gentle, standard, tight, podcast, tutorial). Every decision has a kind, reason, confidence and status. False starts and repeated takes are proposals only. Commands: `plan_cuts`, `apply_cut_plan`, `smart_cut`. Research: [cut intelligence](/research/cut-intelligence.md).
* **Creation**: word-timed captions (`captions.ts`), computed from clip transcripts at render time so they follow every cut. Three looks (classic, bold-pop, minimal) burned in via ASS subtitles. Command `set_captions`. Captions need a transcript, and no speech engine exists yet.
* **Creation**: fit modes (contain, cover, blur) and output presets via `set_format`, including portrait 1080x1920 and square. Portrait and square default to blur. Clip fades, plus 8 ms audio fades at real cuts so joins do not click.
* **Creation**: session history is a tree (`session.ts`). States carry a source (manual, ai or template). You can jump to any state, save named checkpoints, and undo then edit keeps the old branch.
* **Creation**: `packages/protocol` (`@dax/protocol`), the shared request, response and event types for the engine server, desktop UI and agent. Types and zod schemas only. Product spec: [product v1](/specs/product-v1.md), status draft.
* **Creation**: research reports in `docs/research/`: [cut intelligence](/research/cut-intelligence.md), [creator editing styles](/research/creator-editing-styles.md), [industry video templates](/research/industry-video-templates.md), [voice and audio](/research/oss-voice-and-audio.md), [animation and generation](/research/oss-animation-and-generation.md), [effects and transitions](/research/oss-effects-and-transitions.md), [plugin architecture](/research/plugin-architecture.md) and the [open-source radar](/research/open-source-radar.md).
