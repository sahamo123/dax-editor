# ADR 0008: A small custom eval harness instead of an off-the-shelf framework

## Context

We need to know whether a lightweight open model can drive the editor well enough. The questions are about **outcomes on a timeline** after a multi-turn tool-using run (duration, cut count, whether silence remains), plus cost signals (tokens, latency, invalid tool calls). Frameworks surveyed: promptfoo (YAML, prompt/model matrices), Inspect AI (Python, solvers and scorers), DeepEval (Python, pytest-style, LLM-judged metrics). Their license and local-model details were not verified.

## Decision

Build a small harness, `packages/evals`, in TypeScript beside the engine:

- tasks are JSON files; footage is generated by FFmpeg, never committed;
- checks inspect the finished timeline and rendered output, not the model's words;
- `ModelAdapter` is the only integration point for a model;
- a deterministic **oracle** adapter validates the harness itself;
- results are plain JSON, so they can be exported to another framework later.

## Consequences

- No new language or service in the toolchain, and no network needed.
- We own the maintenance. If the harness grows past a few hundred lines of logic, revisit adopting Inspect AI or promptfoo for reporting.

## Alternatives considered

- **promptfoo / Inspect AI / DeepEval:** richer reporting but they would need custom glue to execute our engine and score timelines. Not rejected permanently.
